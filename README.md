# Ежедневник — Telegram Mini App

Личный планировщик с почасовой лентой, повторами, напоминаниями от бота, заметками дня
(текстовыми и голосовыми) и статистикой. Тёмный минималистичный дизайн, русский и английский
интерфейс, офлайн-режим.

## Структура

| Папка     | Что внутри                                                                             |
| --------- | -------------------------------------------------------------------------------------- |
| `shared/` | Типы, парсер быстрого ввода (`14:30 звонок Ивану 45м #работа !!`), логика повторов     |
| `server/` | Cloudflare Worker: API синхронизации, Telegram-бот (grammY), cron напоминаний, статика |
| `web/`    | React + Vite мини-приложение: экраны День / Неделя / Месяц / Список / Итоги, редактор  |

Данные хранятся в Cloudflare D1 и локально в IndexedDB (last-write-wins синхронизация через
`/api/sync`), байты голосовых заметок — на устройстве и в Cloudflare R2.

Нужен **Node 22.6 или новее**: тесты запускаются через `--experimental-strip-types`.

## Локальный запуск

```bash
npm install
cp server/.dev.vars.example server/.dev.vars   # DEV_USER_ID=1 позволяет открыть приложение без Telegram
npm run build --workspace web                  # обязательно: wrangler не стартует без папки web/dist
npm run db:migrate:local --workspace server
npm run dev:server                             # http://127.0.0.1:8787  (API + бот)
npm run dev                                    # http://localhost:5173 (Vite, проксирует /api на 8787)
npm test                                       # тесты парсера и серверных помощников
```

Повседневная работа идёт через Vite на 5173, он сам пересобирает фронт. Сборка в `web/dist` нужна
только для старта воркера: в `server/wrangler.toml` эта папка объявлена источником статики, и если
её нет, wrangler завершается с ошибкой `assets.directory ... does not exist`.

## Деплой на Cloudflare (бесплатный тариф)

Порядок важен: адрес воркера становится известен только после первого деплоя, а биндинги должны
указывать на уже существующие ресурсы.

1. Создайте бота в [@BotFather](https://t.me/BotFather), сохраните токен.
2. Войдите в Cloudflare: `npx wrangler login`.
3. Создайте базу: `npx wrangler d1 create dnevnik` и подставьте выданный `database_id`
   в `server/wrangler.toml`.
4. Создайте бакет для голосовых: `npx wrangler r2 bucket create dnevnik-voice`.
   Это обязательный шаг: в `server/wrangler.toml` объявлен биндинг `VOICE`, а деплой с биндингом
   на несуществующий бакет отклоняется. Голосовые не нужны — удалите блок `[[r2_buckets]]`
   из `server/wrangler.toml`, остальное будет работать без него.
5. Примените миграции: `npm run db:migrate --workspace server`.
6. Первый деплой: `npm run deploy` (из корня). Wrangler напечатает адрес воркера вида
   `https://dnevnik.<account>.workers.dev`.
7. Впишите этот адрес в `WEBAPP_URL` в `server/wrangler.toml`. В репозитории там заглушка
   `dnevnik.example.workers.dev`: если её не заменить, кнопки бота будут открывать чужой домен.
8. Задайте секреты (в папке `server`):
   ```bash
   npx wrangler secret put BOT_TOKEN
   npx wrangler secret put WEBHOOK_SECRET      # 32+ случайных символов A-Z a-z 0-9 _ - (других Telegram не принимает)
   ```
9. Повторите `npm run deploy`, чтобы воркер получил правильный `WEBAPP_URL`.
10. Зарегистрируйте вебхук и кнопку меню бота:
    ```powershell
    # PowerShell
    $env:BOT_TOKEN="..."; $env:WEBAPP_URL="https://dnevnik.<account>.workers.dev"; $env:WEBHOOK_SECRET="..."
    npm run setup:bot --workspace server
    ```
    ```bash
    # bash
    BOT_TOKEN=... WEBAPP_URL=https://dnevnik.<account>.workers.dev WEBHOOK_SECRET=... npm run setup:bot --workspace server
    ```
    Скрипт печатает, откуда взял каждое значение, и отказывается настраивать боевой адрес
    значениями из `server/.dev.vars`.
11. Откройте бота, нажмите `/start` — кнопка меню откроет приложение.

`DEV_USER_ID` должен существовать только в `server/.dev.vars`: он отключает проверку подписи
Telegram и работает лишь на localhost.

## R2 (голосовые заметки)

Голосовые заметки хранятся на устройстве и копируются в Cloudflare R2, чтобы их видели другие
устройства и бот. Метаданные синхронизируются через `/api/sync`, байты — через
`/api/voice/:id/blob`.

При включении R2 Cloudflare может попросить привязать способ оплаты даже на бесплатном тарифе;
лимиты 10 ГБ хранения и 10 млн запросов в месяц при этом сохраняются. Локально `wrangler dev`
эмулирует R2 сам, создавать ничего не нужно.

Если бакет удалить, но оставить биндинг, приложение продолжит работать: заметки записываются и
играют локально, копия в облако не сохраняется (`PUT /api/voice/:id/blob` → 503, голосовые из чата
бота — «не удалось сохранить»). Объекты удалённых заметок чистит cron раз в час, через сутки после
удаления.

## Бот

- `/start`, `/app` — открыть приложение
- `/today`, `/tomorrow` — список задач
- Любой текст — быстрое добавление задачи (`завтра в 9 спорт 1ч #здоровье`)
- Голосовое сообщение — сохраняется в заметки дня: до 15:00 в утро, потом в вечер;
  подпись «утро», «вечер» или «вчера» уточняет, а кнопки под ответом переносят и удаляют
- Напоминания за N минут до задачи, утренний дайджест и вечерний отчёт в выбранное время
  (настройки в приложении)
- Экспорт заметок: кнопка в настройках отправляет Markdown-файл в чат

Бот работает только в личном чате.
