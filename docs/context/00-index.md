# Контекст проекта: почему всё устроено именно так

Эта папка отвечает на вопрос, которого нет в коде: **почему** были приняты те решения, которые в коде видны. Код говорит «что», коммиты — «когда», а здесь собрано «зачем» и «какой ценой».

## Как это получено

Семь агентов параллельно прочитали репозиторий: git-историю (каждый коммит со `stat` и диффом), сервер, клиент, модель данных, голосовые заметки сквозь весь стек, конфигурацию деплоя. Седьмой агент-критик перечитал результат остальных и искал непокрытое и расхождения.

Правило для всех было одно: **каждое решение обязано иметь ссылку на файл со строкой или на хеш коммита**. Где обоснование нигде не записано, оно помечено `INFERRED` и сформулировано как вывод из кода, а не как факт.

Итог: 198 решений, 120 сущностей, 44 открытых вопроса, 12 непокрытых участков, 5 противоречий.

## Как этим пользоваться

Это машинная выжимка, а не документация, подписанная человеком. Ссылки на строки верны на 2026-09-22 и устаревают при первом же рефакторинге. Перед тем как действовать по какому-то пункту, откройте указанный файл и убедитесь сами — выборочная проверка показала точное совпадение, но выборочная проверка это не гарантия.

Достоверность у каждого решения проставлена явно:

- `EXTRACTED` — обоснование записано в коде, комментарии или сообщении коммита;
- `INFERRED` — вывод из кода, автор так не писал;
- `AMBIGUOUS` — агент не уверен.

## Три линии, вокруг которых крутится вся история

**Синхронизация.** От наивного LWW по клиентскому `updated_at` к серверному курсору `synced_at` (миграция `0001`), перекрытию курсора в 60 секунд и правилу «явное завершение задачи бьёт ночной авто-перенос». Причина всех трёх правок одна: часам устройства нельзя доверять.

**Выживание бота.** Под вебхуком любая ошибка обязана отвечать `200`, иначе Telegram часами передоставляет тот же апдейт вместе со всеми побочными эффектами. Отсюда же подставная identity бота и фоновый `getMe`.

**Голосовые заметки.** Спроектированы контрактом (`docs/voice-notes-contract.md`) до написания кода. Ключевое решение — local-first: байты живут на устройстве, копия уходит в R2, перекодирования нет нигде.

## Что критик нашёл сверх этого

Самое важное из `07-gaps.md`, проверенное вручную по коду:

- `HORIZON = 30` в `ListView.tsx:10` — задачи дальше месяца не видны ни в одной секции списка, хотя в базе они есть.
- `cors({ origin: (origin) => origin || '*' })` в `index.ts:36` — API отражает любой `Origin` и разрешает заголовок `Authorization`. Решение осознанное, но нигде не обосновано.
- Две разные регулярки для одного и того же id голосовой заметки: свободная `/^[0-9a-f-]{36}$/i` в `validate.ts:41` и каноническая в `voice.ts:17`. Заметка с неканоническим id пройдёт синк, но все операции с её байтами будут отдавать `404`.
- Миграция `0001` объявляет независимость курсора от клиентских часов и тут же бэкфилит `synced_at` из `updated_at`, то есть ровно из клиентских часов.
- Перекрытие курсора (60 с) равно периоду автосинка (60 с), поэтому каждый штатный пулл заново скачивает результат предыдущего.
- Нет ни удаления аккаунта, ни экспорта задач: выгрузить можно только заметки дня в Markdown.
